Request Data Flow
1
User changes a filter in FilterBar.vue. The useFilters.js singleton composable updates its shared reactive refs (selectedWarehouse, selectedCategory, selectedMonth, selectedStatus). All views share the same filter state automatically.
2
View detects change via a watch on the filter refs. It calls the relevant method on api.js, which builds a URLSearchParams query string from active filters and fires an Axios GET request to http://localhost:8001/api/....
3
FastAPI receives the request in main.py. apply_filters() chains warehouse → category → status passes, then filter_by_month() handles direct month strings (e.g. 2025-03) or quarter tokens (Q1-2025 → ['2025-01','2025-02','2025-03']) via the QUARTER_MAP dict.
4
Pydantic validates and serialises the filtered list. FastAPI returns JSON with a 200 response.
5
Vue updates the DOM. Raw API data lands in a ref (e.g. allOrders). Computed properties (filteredOrders, chart data, KPI totals) derive automatically from it. Currency is converted via currency.js at a fixed 1 USD = 150 JPY rate if the user has selected Japanese locale.
API Endpoints
Method Path Filters / Notes
GET /api/inventory warehouse, category
GET /api/inventory/{item_id} Single item by ID
GET /api/orders warehouse, category, status, month
GET /api/orders/{order_id} Single order by ID
GET /api/dashboard/summary All filters — aggregated KPIs
GET /api/demand No filters
GET /api/backlog No filters — enriched with has_purchase_order flag
GET /api/spending/summary Spending group — no filters
GET /api/spending/monthly
GET /api/spending/categories
GET /api/spending/transactions
GET /api/reports/quarterly Calculated from orders — Q1–Q4 2025
GET /api/reports/monthly-trends Month-over-month aggregation from orders
Not yet implemented in backend: api.js defines task methods (getTasks, createTask, deleteTask, toggleTask) and purchase-order methods (createPurchaseOrder, getPurchaseOrderByBacklogItem) that have no corresponding routes in main.py.
